# Safe to touch

Defaults for step 6 of [SKILL.md](SKILL.md). The tiers describe **who should review a change**, not whether a designer may open the file. Every tier can be read.

## Repo rules first

Before applying the defaults, collect the repo's own rules. Each one overrides a default:

- `CODEOWNERS` (`.github/`, `docs/` or the root): a path owned by a named team needs that team's review. Report the owner next to the path.
- Contributing docs, `AGENTS.md`, `CLAUDE.md`, editor rules: statements such as "do not edit `components/ui` directly" or "all colors come from tokens".
- File headers: "auto-generated", "do not edit", "generated by".
- Lint rules: `no-restricted-imports` or `no-restricted-syntax` entries that ban raw library imports or raw values.
- A design system shipped as a versioned package: its source lives elsewhere, so changes go to that repo, not here.

## Safe to change

Changes whose effect stays on the screen being edited. Before listing a file here, count its importers: a page file that also exports data other routes import is not a leaf.

- Copy in JSX, and in locale files when the repo uses i18n (`locales/`, `messages/`, `*.json` keyed by language). When copy lives in a locale file, change it there; a literal string in JSX would bypass translation.
- Layout and styling inside a page or route file (`app/**/page.tsx`, `pages/*.tsx`, `routes/*`).
- Leaf components: one or two importers, no data fetching, no state shared with other screens.
- Static assets in `public/` or `assets/` when they replace an image only that screen uses.
- Stories (`*.stories.tsx`) and component docs.

## Change with care

Safe to edit, but every screen that uses it changes. Measure reach before the edit: count importers, list the routes they render on, and check them after the change. If `component-impact` is installed, tell the user to run `/component-impact`; it runs only when the user starts it.

- Shared primitives: `components/ui/*`, `packages/ui`, library wrappers. Adding a variant is lower risk than changing a default one.
- Tokens and theme: the `@theme` block, `:root` variables, `tailwind.config` `theme`, `createTheme` files, token JSON sources.
- Global CSS: `globals.css`, `index.css`, resets, base layers.
- Root and shared layouts: `app/layout.tsx`, `_app.tsx`, `_document.tsx`, shell components (header, nav, footer).
- Icons and shared images used across screens.

## Ask an engineer first

Changes that affect data, security, the build or other people's work. Reading them is fine. Edit only after an engineer agrees, and say so in the pull request.

| Area | Typical paths |
|---|---|
| Data fetching and state | `fetch` or client calls inside components, `lib/api/`, `services/`, `queries/`, `hooks/use*Query*`, stores (`store/`, Redux, Zustand, Pinia) |
| Server code | `app/api/`, `pages/api/`, route handlers (`route.ts`), server actions (`"use server"`), loaders and actions in Remix or React Router |
| Auth and access | `middleware.ts`, `auth/`, session and permission checks, role-based conditionals in components |
| Config and build | `next.config.*`, `vite.config.*`, `tsconfig.json`, `postcss.config.*`, ESLint and Prettier configs, `tailwind.config` plugins and content paths, CSS `@layer` order declarations that decide which styling system wins |
| Dependencies | `package.json` dependencies and scripts, lockfiles, `.npmrc`, `.nvmrc` |
| Environment | `.env*` files other than the designer's own local file, env schemas (`env.ts`, `env.mjs`) |
| Generated files | `__generated__/`, `generated/`, `*.gen.*`, `*.generated.*`, GraphQL and OpenAPI clients, token build output, `dist/`, `build/`, `.next/` |
| Data and schemas | `prisma/`, `migrations/`, `schema.graphql`, seed scripts |
| Product signals | analytics and tracking calls, feature flag checks, experiment variants |
| Delivery | `.github/workflows/`, `Dockerfile`, deploy configs, `CODEOWNERS` itself |
| Tests | Test files and snapshots: update only when the UI change breaks an expectation, and name each one in the pull request |

## Edge cases

- **A presentational component that fetches.** A component that renders a card and also calls an API is in the ask tier for its data lines and the safe tier for its markup and classes. Say which lines are which.
- **One file holds the whole app.** Small apps keep state, storage and markup in one component. Give the tiers by line range ("lines 1 to 99: state and storage, ask first; lines 100 to 210: markup, safe except the handlers and conditions").
- **Copy inside a care-tier file.** The page title in a root layout's metadata is copy, so it is safe, even though the file around it is change with care.
- **Persisted data.** A `localStorage` key or a saved data shape is in the ask tier: changing it breaks data users already saved.
- **Conditional rendering.** A condition based on a role, plan or flag (`user.isAdmin && ...`) is product logic, even inside a safe file. Leave it unchanged.
- **Hard-coded values in a safe file.** Replacing a raw hex with an existing token is safe when the token's value matches. Adding a new token is change with care.
- **Copy with legal or pricing meaning.** Terms, prices, plan limits and consent text are safe to edit technically, but name them for review by whoever owns them.
